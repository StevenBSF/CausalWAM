## 3. 已有较短 P-v2 pilot 结果（仅用于方向证据）

旧的 1,800-step、seed1 P-v2 pilot 使用相同作者基座，但 paired state bank 只有 720 states，训练预算也不同。100 episodes/task/domain 的结果是：

| Task | C1 Clean | C3 Clean | Δ | C1 Random | C3 Random | Δ |
|---|---:|---:|---:|---:|---:|---:|
| Place A2B Left | 81% | 77% | −4 pp | 81% | 84% | +3 pp |
| Open Microwave | 28% | 42% | +14 pp | 64% | 69% | +5 pp |
| Move Stapler Pad | 25% | 21% | −4 pp | 33% | 39% | +6 pp |
| Macro | 44.67% | 46.67% | +2.00 pp | 59.33% | 64.00% | +4.67 pp |

依据是 `FastWAM/docs/pv2_actiondit_followup.md` 和对应 create-only report。它说明“解冻 ActionDiT + contrastive”值得进行完整训练，但不能代替 Pair-280 matching C1/C3。

## 4. H100 上的下一步顺序

### Step A：拉代码和 artifacts

```bash
git clone https://github.com/StevenBSF/CausalWAM.git
cd CausalWAM/FastWAM
```

从 ModelScope 按机器任务下载：

- 只训练：`models-runtime`、`official-three-task-subset`、`native50hz-paired`、`official-text-cache`、`pair280-layer16-cache`、`provenance-small`。
- 只评测已有 C3：`models-runtime`、`pair280-seed1-c3-final`、`robotwin-assets`、`provenance-small`；无需下载 70GB Layer-16 tensor shards和 official train data。
- 原样续训 seed1/C3：在训练 bundle 之外再下载 `pair280-seed1-c3-resume-step18215`。平时不要上传/下载其他 9 个历史 optimizer states。

### Step B：保持路径身份或重新物化

现有产物 SHA 审计同时记录了源服务器绝对路径。最快且最不容易破坏 lineage 的迁移方式，是在 H100 上用 symlink 复现以下逻辑布局：

```text
/mnt/cpfs-E/baoshifeng/CausalWAM/FastWAM        -> cloned_repo/FastWAM
/mnt/cpfs-E/baoshifeng/FastWAM/checkpoints      -> downloaded/checkpoints
/mnt/cpfs-E/baoshifeng/FastWAM/data/robotwin2.0 -> downloaded/robotwin2.0
/root/fastwam_policy_artifacts/pair280_layer16_v1 -> downloaded/pair280_layer16_v1
```

如果没有权限创建这些路径，不要手工编辑审计 JSON；应让代码针对新路径重新 materialize lineage/config，并产生新的 create-only migration manifest。

### Step C：环境与 CPU gate

在 H100 上新建环境并按 FastWAM/RoboTwin README 安装依赖。然后执行：

```bash
cd CausalWAM/FastWAM
export PYTHONPATH="$PWD/src:$PWD${PYTHONPATH:+:$PYTHONPATH}"

pytest -q experiments/robotwin/policy_content_adapter/tests

python -m experiments.robotwin.policy_content_adapter.pair280_protocol \
  verify-cache \
  --manifest /root/fastwam_policy_artifacts/pair280_layer16_v1/cache_manifest.json \
  --verify-shard-hashes
```

70GB cache 全量 SHA 只需在下载后验证一次，但必须 PASS 才能训练。

### Step D：先做 8 卡 H100 smoke

H100 上不要直接跑 18,215 steps。先用 8 卡 3-step smoke 验证：

- bf16、torch/DeepSpeed/Accelerate/NCCL 版本兼容；
- 8 个 rank 均加载相同 base/cache；
- ActionDiT、Head、GCA 有 finite gradient 和参数更新；
- checkpoint/save/resume 路径可写；
- global official batch=128，paired global groups=16。

当前 seed1/C3 runner 示例：

```bash
GPU_IDS=0,1,2,3,4,5,6,7 \
ARTIFACT_ROOT=/root/fastwam_policy_artifacts/pair280_layer16_v1 \
MODEL_BASE=/mnt/cpfs-E/baoshifeng/FastWAM/checkpoints \
PHASE=smoke RESUME=NO CONFIRM_GPU_WORK=YES \
bash experiments/robotwin/policy_content_adapter/run_pair280_seed1_c3.sh
```

注意：这条现有命令是 seed1/C3 专用，不是 matching C1 命令。

### Step E：实现并训练 matching Pair-280 seed1/C1

修改 materializer/runner，使其显式接受 `--control c1_architecture_only|c3_ours` 与 `--training-seed`。正式 seed1/C1 必须与已完成 seed1/C3 保持：

- 同一个作者 base checkpoint、stats、P-v2 和代码协议；
- 同一个 seeded Head/GCA 初始张量；
- 同一个 official sample 顺序、paired state 顺序、step RNG、action noise/timestep；
- 同样 18,215 steps、8 GPUs、official batch 16/GPU、paired groups 2/GPU；
- 同样 optimizer/scheduler、ActionDiT LR `1e-5`、Head/GCA LR `1e-4`；
- 同样 save-every-2000 与 optimizer state；
- 唯一允许的训练差异：C1 `lambda_contrastive=0.0`，C3 `lambda_contrastive=0.1` 以及由此直接派生的 contrastive gradient flag。

materialize 后先做 config diff allowlist audit，再 smoke，最后才正式训练。

### Step F：matching online evaluation

完成 C1 后，C1/C3 都用相同的 simulator seed53、作者原生 episode filtering、每格 100 episodes：

```text
Place A2B Left: Clean 100 + Official Random 100
Open Microwave: Clean 100 + Official Random 100
Move Stapler Pad: Clean 100 + Official Random 100
```

主比较是 task-level 和 macro `C3−C1`。当前评测只保证相同起始 seed/设置，不声称最终 expert-accepted episodes 一一配对。

### Step G：再决定 seeds 2/3

只有 seed1 matching Pair-280 结果支持方法方向时，再并行运行 seeds 2/3 的 C1/C3。每个 seed 内必须严格配对；跨 seed 用于报告 mean ± std。最终 seed59 bank 在协议锁定前不得用于调参。

## 5. H100 与 RoboTwin 渲染的重要边界

H100 是训练卡，服务器未必暴露 NVIDIA Vulkan/graphics device。在线 rollout 前必须逐卡运行：

```bash
python -m experiments.robotwin.policy_content_adapter.robotwin_gpu_runtime \
  preflight --gpu-id 0
```

如果 Vulkan 或 SAPIEN `can_render` 失败：

- H100 仍可用于训练、cache 消费和 checkpoint 生成；
- 不要尝试通过关闭渲染检查来“跑评测”；
- 将 checkpoint/sidecar 传回当前 RTX PRO 5000 服务器，用其已验证的 Vulkan/SAPIEN 环境完成 6 卡 rollout。

## 6. 不要做的事情

- 不要重新训练已经完成的 Pair-280 seed1/C3，除非 SHA 校验失败。
- 不要复用 720-state 旧 cache 冒充 Pair-280 25,200-state cache。
- 不要把 1,800-step pilot 与 18,215-step Pair-280 结果混表。
- 不要删除或覆盖 create-only manifests、旧失败目录或已有 checkpoint。
- 不要上传 261GB 的全部历史 optimizer states；默认只保留最终部署 checkpoint，确需续训时只传最后一个 state。
- 不要把 seed53 development rollout 称为 final test。
